# Deribit Crypto Tracker API

Асинхронное веб-приложение на FastAPI для мониторинга индексных цен криптовалют (`btc_usd`, `eth_usd`) в реальном времени с интегрированным фоновым сборщиком данных на Celery и постоянным хранением истории котировок в СУБД PostgreSQL.

## 🛠 Технологический стек
* **Язык разработки:** Python 3.12 (Slim-дистрибутив)
* **Веб-фреймворк:** FastAPI (Асинхронный)
* **Фоновые задачи и планировщик:** Celery + Celery Beat
* **ORM:** SQLAlchemy 2.1
* **Валидация и конфиги:** Pydantic v2 + Pydantic Settings
* **Драйверы базы данных:** asyncpg (асинхронный для API) / psycopg (v3 с бинарниками для Celery)
* **СУБД:** PostgreSQL 13+
* **Тестирование:** pytest + pytest-asyncio + httpx (AsyncClient) + aiosqlite
* **Контейнеризация:** Docker / Docker Compose

## 🐳 Инструкция по разворачиванию в Docker (Двухконтейнерная сборка)

Вся инфраструктура (СУБД PostgreSQL, Веб-сервер FastAPI, Celery Воркер и Планировщик Beat) разворачивается одной командой.

### 1. Подготовка конфигурации окружения
Переименуйте файл **`.env.example`** в **`.env`** или создайте в корневой директории проекта файл **`.env`** следующего содержания:
```ini
# НАСТРОЙКИ ИМЕН ДЛЯ DOCKER
CONTAINER_NAME_BASE=deribit_db
CONTAINER_NAME_APP=deribit_app

# НАСТРОЙКИ ИНТЕГРАЦИИ С БИРЖЕЙ DERIBIT
DERIBIT_BASE_URL=https://deribit.com
CRYPTO_TICKERS=["btc_usd","eth_usd"]
FETCH_INTERVAL_SECONDS=60

# НАСТРОЙКИ ДЛЯ СУБД POSTGRESQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=secret_password
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=crypto_tracker_db
```

### 2. Команда запуска
Из корневой папки проекта (где находится файл `docker-compose.yml`) выполните команду сборки и старта:
```bash
docker-compose up --build
```

**Что произойдет автоматически:**
1. Развернется изолированный контейнер базы данных PostgreSQL `deribit_db`. Данные монтируются в именованный том `pgdata`, что гарантирует сохранность истории цен при перезапуске инфраструктуры.
2. Контейнер приложения `deribit_app` с помощью механизма `healthcheck` дождется полной готовности СУБД к приему соединений (утилита `pg_isready`).
3. Оркестрационный скрипт `entrypoint.sh` параллельно запустит асинхронный веб-сервер FastAPI и фоновые процессы Celery. FastAPI автоматически развернет схему таблиц при холодном старте через хук жизненного цикла `lifespan`.

### 3. Проверка и тестирование API
* **Интерактивная документация Swagger UI:** Перейдите в браузере по адресу: [http://localhost:8000/docs](http://localhost:8000/docs).
* **Сбор данных:** Раз в 60 секунд (настраивается через `FETCH_INTERVAL_SECONDS`) Celery Beat отправляет задачу воркеру, который совершает параллельный сетевой запрос к Deribit, извлекает Index Price и сохраняет пачку данных в Postgres.

## 🚀 Локальный запуск (Без Docker)

Если вам необходимо запустить проект напрямую на хост-машине (например, для локальной отладки):
1. Установите и запустите локальную PostgreSQL. Создайте базу данных `crypto_tracker_db`.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Запустите веб-сервер: `uvicorn app.main:app --reload` (порт 8000).
4. Запустите сборщик Celery в соседнем окне терминала:
   * *Для Linux/macOS:* `celery -A app.tasks.celery_app worker -B --loglevel=info`
   * *Для Windows:* `celery -A app.tasks.celery_app worker -B --loglevel=info -P solo`

## 🧪 Запуск автоматизированных Unit-тестов

Тесты полностью изолированы от боевой базы данных и не требуют запущенного Docker или PostgreSQL. Они используют подмену базы данных (*Dependency Overrides*) на легковесную СУБД SQLite в оперативной памяти (`:memory:`).

Для запуска тестов выполните в корне проекта:
```bash
python -m pytest -v
```
Тесты проверяют: возврат пустых структур, обработку ошибок 404 при отсутствии котировок, корректность сортировки сквозного сценария `INSERT -> SELECT`, а также работу умного фильтра диапазонов дат.

## 🧠 Section: Design Decisions (Принятые архитектурные решения)

В ходе проектирования архитектуры и реализации сервиса были приняты следующие ключевые технические решения:

### 1. Двухконтейнерная архитектура Docker (Оптимизация слоев и процессов)
Вместо избыточного разделения кодовой базы Python на 3 отдельных контейнера (FastAPI, Celery Worker, Celery Beat), вся бизнес-логика упакована в **один контейнер приложения**. Параллельный запуск изолированных процессов организован с помощью оркестрационного скрипта `entrypoint.sh` в связке с фоновым ветвлением процессов Linux (`&`). Это снижает накладные расходы на виртуализацию Docker, ускоряет сборку и обеспечивает детерминированный запуск через Docker-директиву `condition: service_healthy` (ожидание реального поднятия сети СУБД, а не просто старта контейнера).

### 2. Использование реляционной СУБД в качестве брокера задач Celery
Чтобы исключить оверэнжиниринг и опустить необходимость внедрения дополнительных инфраструктурных узлов (таких как Redis или RabbitMQ), в качестве транспорта очередей Celery выбран встроенный драйвер `sqla` (SQLAlchemy). Задачи и расписание хранятся в служебных таблицах базы данных PostgreSQL. Это снижает требования всей системы к оперативной памяти и упрощает локальное развертывание.

### 3. Точные типы временных меток UNIX через `time.time_ns()` без потери точности
В соответствии с ТЗ, временные метки сбора данных сохраняются в формате `UNIX timestamp`. Стандартный метод `int(time.time())` возвращает системное время как `float` и выполняет приведение типов на уровне Python, что при работе с большими числами может вызывать микроскопические погрешности округления. В модуле `database.py` используется функция `time.time_ns() // 1_000_000_000`, выполняющая целочисленное деление наносекунд на уровне процессора. Функция передается в SQLAlchemy как объект (`default=get_current_timestamp` без скобок), что гарантирует вычисление времени строго в миллисекунду фактического выполнения SQL-запроса `INSERT`, а не в момент импорта модуля.

### 4. Абстракция формата хранения от интерфейса API («Умный фильтр» дат)
Хранение меток времени в формате целых чисел `int` в БД обеспечивает максимальную производительность индексов. Однако требование от пользователя передавать сырые UNIX-секунды в параметрах запроса — плохая практика проектирования API. Эндпоинт `GET /prices/filter` принимает человекочитаемые строки формата ISO (`datetime`), которые FastAPI валидирует автоматически. Внутри бизнес-логики реализован «Умный фильтр»: если пользователь передает чистые даты без указания часов (например, диапазон от `2026-10-15` до `2026-10-15`), код автоматически расширяет время окончания до `23:59:59` текущих суток, исключая проблему пустых ответов СУБД.
